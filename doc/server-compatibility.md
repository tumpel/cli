# Server compatibility work

Session scenarios run the real binary against a local HTTP server. They cover list, get, start, start-from-issue, stop, tag replacement and patching, archive, delete, stop failures and credential handovers. Unknown enum values and failure reasons, changed field shapes, unreadable bodies, unexpected statuses and unfamiliar refusal codes produce one update notice. Printable JSON continues; an unreadable response exits with code 3. Extra fields do not request an update, and known refusals keep their explanation and code 1.

Successfully decoded generated Unrecognised variants remain pending [the protocol generator change](https://github.com/tumpel/protocol/pull/104), its release, and a bump to the exact release candidate tag. The current scenarios exercise the JSON display fallback and the existing unrecognised problem code; they do not prove handling of the new enum variants.

Stage 2 adds scenario coverage for turn, transcript (including session transcript), snapshot, persona, secret set, subscription, trigger, host, harness, config, limits and events/wait. The remaining families are login/identity, tenants/members/invitations, devices, release, connectors, GitHub/connections/OAuth grants, metrics, prebuilds/templates, Claude setup and OpenRouter. It also audits their command-specific decoders and handles the new Unrecognised variants after the protocol pin changes. Turn wait is removed; event waits use fixed polling intervals, and scenario waits must use a fake clock.
